はじめに

この教材の目的

1. この教材は、 ETロボコン に参加されるみなさんに、モデル作成に必要となる知識やスキル取得の機

会を提供することを目的に作成しています。

2. この教材は、「 権利・諸注意 」 記載の事項を理解、遵守の上、活用してください。

開発環境・要素技術セミナー の役割

3. このテキストでは、 ETロボコン に参加されるみなさんに、参加者にとって最低限必要となる、ソフ

トウェア開発の開発環境や走行体の動作に関する技術要素について説明します。

4. このテキストの役割は、技術要素の基本的な知識を得る機会を提供することです。 具体的でより詳細

な説明や演習は、「 要素技術とモデルを開発に使おう 」を参照してください。ただし、このテキス

トや「 要素技術とモデルを開発に使おう 」で全ての事柄をフォローしている訳ではありません。必

要に応じて各自で調査してください。

アイコンの説明（admonition）

5. 読者に情報や注意を促したいことがあって、それを目立たせたいときは、次のよう

な「Admonitions」アイコンを用います。

告知（NOTE）。みなさんが覚えておくとよい追加情報など。

ティップ（TIP）。覚えておくと便利なちょっとしたヒントやコツ。

重要（IMPORTANT）。見落とすと期待通りの結果が得られないことがら。

注意（CAUTION）。慎重に行動する（注意を払う）ことを勧めることがら。

警告（WARNING）。守らないと破損や怪我などにつながることがら。

2.2.1 タッチボタン

24. 実機走行体の後方にはタッチボタンがあります。

• 走行体の操作者は、タッチボタンに触れたり、タッチボタンを押し込んだり（押し続けたり）で

• フォースセンサーの状態は、「SPIKEフォースセンサーAPI」を使って取得できます。
• 走行体制御ソフトウェアは、フォースセンサーからの取得値を使ってタッチボタンの操作状態を

取得できます。

2.2.2 車輪

25. 実機走行体の左右には、車輪が装着されています。

• 左右の⾞輪にはそれぞれ独立したモーターが接続されていて、個別に車輪を回転させることがで

きます。

• モーターには、「SPIKEプライムMアンギュラーモーター」を使っています。
• 走行体制御ソフトウェアは、「SPIKEモーターAPI」を使ってモーターを駆動させることで、車輪

の回転の向きや回転速度を設定できます。

• モーターに与えるパワー（PWM値）が大きいほど、車輪の回転が速くなります。
• モーターにはエンコーダーが付いています。エンコーダーを使うとモーターの回転角度や回転方

向を取得できます。

• 走行体制御ソフトウェアは、エンコーダーから取得できる値によって、車輪の向きや回転角度を

調べられます。

2.2.3 アーム

26. 実機走行体の正面下部には、アームが装着されています。

• アームを動かすことによって、ブロックを持ったり、弾いたりできます。
• アームはモーターに接続されていて、アームを上下方向にスイングさせることができます。（根

元の軸を起点にアームが上下方向に回転します）

• モーターには、「SPIKEプライムLアンギュラーモーター」を使っています。
• 走行体制御ソフトウェアは、「SPIKEモーターAPI」を使ってモーターを駆動させることで、アー

ムをスイングさせる向きや変位を設定できます。

• モーターに与えるパワー（PWM値）が大きいほど、アームのスイング速度が速くなります。
• モーターにはエンコーダーが付いています。エンコーダーを使うとモーターの回転角度や回転方

向を取得できます。

5.1 RTOSの特徴

第5章

RTOS

62. RTOS(Real-time operating system)とは、システムの要求に対して、決められた時間内に確実に処

理を完了することが要求されるシステムに特化したオペレーティングシステムです。

63. リアルタイム性能を要求される組み込みシステムには、自動車、産業ロボット、医療機器、航空宇宙

システム、軍事システムなどがあり、 リアルタイムOSは、特定の目的を果たすために作られる組み

込み機器に使用されルコとが多いです。

64. ETロボコンでは、RasPike-ART環境およびシミュレータで使用するetrobo環境でTOPPERSプロジ

ェクトが開発した組み込みシステム向けのRTOSの「 TOPPERS/ASP3 」を利用しています。

65. 本章ではRTOSの概要を説明します。

5.1 RTOSの特徴

5.1.1 リアルタイム応答性能

66. タスク（スレッド）切り替えや割り込み応答の時間をなるべく短くするように作られています。その

ため、汎用OSに比べると機能に制限がある場合があります。以下のような動作に適しています。

• ⼀定時間内に、指定した動作を実⾏（ロボットの制御など)
• ETロボコンではライントレース走行制御など、時間制約の厳しい処理の実行

5.1.2 安価なシステムでも動作

67. 汎用OSに比べると制限がある反面、低機能なプロセッサ（＝安価なプロセッサ）や少ないメモリでも

動作するように構成することができるものが多いです。下記はその例です。

• MMU（メモリ管理ユニット）を持たないプロセッサでも動作
• 動的なメモリ管理を行わせず、静的にメモリを確保して動作させることで使用メモリ量を減らす
• 必要な機能だけを選択して構成し、ROMやRAMの使用量を減らす

5.2.2 ハンドラ

• イベントが発生したときに呼ばれる処理をハンドラと呼び、特にハードウェアによる割り込み通

知を割込みハンドラと呼びます。

• ハンドラには一定周期で起動される周期ハンドラ、特定時刻または一定時間後に起動するアラー

ムハンドラなどがあります。

5.2.3 タスクの優先度

73. RTOS らしい特徴として、タスクの優先度があります。

• 最も優先度の⾼いタスクにCPU を割り当て実⾏します。
◦ そのタスクが終了したり待ち状態になるまで、それより低い優先度のタスクは実⾏されませ

ん。

◦ 同じ優先度のタスクが複数動作できる状態にある場合は、一定時間で切り替わるといった方式

（ラウンドロビン）で実行されるように構成できるものが多いです。

5.2.4 定周期動作

• ⼀定の時間間隔で処理を実⾏します。
• RTOS では、定周期動作間隔を極めて正確にすることが可能です。

5.3 定周期動作の実現方法

74. RTOSの機能を使った方式として、よく使われる2つの方法を紹介します。

5.3.1 周期アラーム

• ループの中で、休止と起床を繰り返す
• 休止方法としては、イベント待ちなどがある
• 周期的に起こすためには、RTOSのアラーム機能を使用して、そこからイベントを発行してタスク

を起床させる

5.3.2 周期起動タスク・周期ハンドラ

• 複数のタスクを動かす時の主な⽅策
• ⼀定周期で繰り返しタスクを起動（実⾏）させる
• RTOSは、タスク起動の間隔が数[msec]でも問題ない

sleep関数などを使って一定時間ごとに処理を繰り返し実行させる方法もありますが、この場合

はsleepに入ってからの経過時間を基準に再開されるため、意図しない処理時間の揺らぎが起き

ると、正しい周期で実行されないことがあります。 例えば、100msec周期で処理したい場合

に、1周期内での処理時間が 20msec かかるとします。このときsleepの設定値は 80msecとなり

6.1 ロバスト設計

85. ロバスト設計とは、信頼性向上を図る設計手法の１つです。 製品に使われている部品の精度にバラつ

きがあった場合や、使用環境や使用条件の違いによる外乱があった場合でも、安定した性能を出す仕

組みをロバストネス(robustness)と言います。

• 製品に使われている部品には、精度や性能のバラつきがあります。 また、使用環境や使用条件の
違いによって部品の劣化にもバラつきがあります。 さらに、周辺の明るさや走行面の凹凸といっ

た環境の影響が、システムの動作を乱す場合もあります（このような影響を外乱と呼びます）。
• システムの信頼性を向上するには、バラつきや外乱の影響を最小限にとどめる必要があります。
制御工学におけるロバストネス（robustness）とは、そのような仕組みや性質のことを指しま

す。 また、頑強性（がんきょうせい）、頑健性（がんけんせい）、堅牢性（けんろうせい）、ロ

バスト性などと呼ぶこともあります。

86. システムがロバストネスを持つように設計することを、ロバスト設計（Robust Design）と呼びま

す。

87. 組込みシステムを安定して動作させるために、 「 ロバスト設計で考慮することがら 」に示すような影響

を検討します。 これらの影響はなくしたり避けたりすることができないので、動作に与える影響がで

6.2 部品の個体差によるバラつき

90. ETロボコン の走行体には複数のモーターやセンサーが使われています。 モーターやセンサーは、部

品ごとに定められた品質で製造されていますが、コストとの兼ね合いもあり、まったく同じには作ら

れていません。 使用上許容できる範囲内に収まるように製造されていますが、それ以上の細かい部分

では差異が残ります。 これが製造時点で生じている個々の違いとなり、個体差と呼ばれています。

91. たとえば、車輪に接続されている2つのモーターに同じPWM値を出力して走行させてみましょう。走

行体は前進（または後退）します。 ですが、そのまま数メートル走行させると、走行体は左右どちら

かへ反っていってしまいます。

92. このことは、2つのモーターは、同じPWM値の指令値を与えても、同じ速度や回転数で回っていない

ことを意味します。 つまり、個々モーターには、個体ごとに少しずつ性能の違いといったバラつき（

個体差）があるのです。 短距離では問題なくても、長距離になったときにバラつきが問題になること

があります。

93. センサーの読み取る値も同様です。 製造時から素子自体に個体差があり、素子ごとの劣化もまちまち

ですから、センサーごとにバラつきが生じます。 たとえば、カラーセンサーで色や反射光を読み取る

ときの値は、個々のカラーセンサーごとに少しずつ異なっています。

6.3 環境によるバラつき

94. ETロボコン の競技で使うコースには、白色の布地に黒色や青色で印刷された線が引かれています。

95. 走行コースが設営される会場では、天井のあちこちに照明が設置されていて、コースを明るく照らし

ています。 会場によって、照明に使われている光源は異なります（LED、白熱灯、蛍光灯、水銀灯な

ど）。 光源の種類や明るさが異なれば、当然、カラーセンサーが取得する色や反射光の明るさも変わ

116. オンオフ制御のライントレースでは、常に「右旋回」「左旋回」を繰り返していています。 このよう

に制御動作そのものが目標値の周辺で安定せずに波打つことを、「ハンチング」と呼びます。

117. オンオフ制御は単純でわかりやすい方式ですが、このハンチングをなくすことができないという欠点

があります。 モーターに与えるPWM値を大きくしても、旋回の度合いが大きくなるだけで、あまり

走行速度は上がりません。 むしろ、波打ちがひどくなる結果、ラインから外れてしまう場合が増えま

す。

118. オンオフ制御でハンチングをなくせないのは、たくさんある測定値を、しきい値で2つの状態にまと

めているからです。 もっと滑らかに走行させるには、オンオフ制御においてオンとオフに分けている

値を、もっと多くの状況に分けて動作を調整する必要があります。

6.6.2 比例制御（P制御）

119. オンオフ制御よりも無駄な動き（ジグザグな動き）が少なく、安定してた走行のためには、旋回する

量を制御する制御方式を紹介します。 ここでは、代表的なものとして、比例制御とPID制御を紹介し

ます。

120. 比例制御（P制御、proportional control）は、フィードバック制御の中で最も基本的な制御方式で

す。 現在の制御量（制御対象への入力）と目標値との偏差に比例するよう操作量を増減させることが

特徴で、出力を目標値に近づけるという最も基本的な役割を持っています。具体的には、入力と目標

値の偏差が大きいときは操作量が大きくなります。入力と目標値の偏差が小さいときは操作量も小さ

くなります。 その程度をPゲインと呼ばれる定数で調整します。フィードバック制御系を用いること

で、不安定な制御対象をより安定して制御できるようになり、外乱の影響を低減できます。 Pゲイン

を上げると即応性が高まる反面、上げすぎるとシステムの出力が振動的な挙動になります。

121. また、P制御ではオフセット（定常偏差）が発生するため、出力値を目標値と完全一致させることは

できません。

122. ライントレースするケースを例にして説明します。 オンオフ制御するプログラムで生じてしまう無駄

な動き（ジグザグな動き）を解消するために、比例制御（P制御）を取り入れ、カラーセンサーの値

を用いて左右に曲がる強度を制御します。

旋回量は徐々に収束していく

6.6.3 PID制御

123. PID制御はフィードバック制御の一種で、温度制御やモーター制御などさまざまな自動制御に使われ

例制御（P制御）に加えて、積分制御（I制御）と微分制御（D制御）も行うことから、「PID制御」

と呼ばれます。

しょう。その後、観測した状況に応じてI制御やD制御を追加すると、余分な複雑さを持ち込まず

に済みます。また、それぞれの制御方式の意味や効果も理解しやすいでしょう。

6.7 ユーザーインターフェイス

131. ユーザーインターフェイスは、ソフトウェア分野での一般的な用語としての意味は「ユーザーがある

たり、システムの画面デザインや使用方法などを指したりと、非常に広い意味で使われています。

の用語として取り上げています。

6.7.1 アンサーバック

133. アンサーバックは、動作指令に従って正しく作動していることを返すこと、または、その信号のこと

です。

• 使用例1：利用者のスイッチ操作をシステムが受け付けたことを、ブザー吹鳴によって利用者に通

知する

• 使用例2：システム、または、ソフトウェア上で何らかのイベントが起きたことを、LED点灯によ

って利用者に通知する

ETロボコンでは、走行体が何らかのイベントを検出したときにブザー吹鳴やLED点灯をすること

で、利用者に何らかの事象が起きたことを通知する使い方が多いです。

6.8 開発支援

6.8.1 計測

• ソフトウェア内部の動きは目で見て確認できないため、ソフトウェア内部の動きを「見える化」

して確認する必要があります。

• 確認したい変数の値をソフトウェアの処理周期に合わせてサンプリングを行い、計測データを作
成します。作成した計測データは、システム外部と繋がるインターフェイスを介して出力する

か、システム内部に保存しておき、あとから取り出せるようにします。

• ソフトウェア開発者はこの計測データを解析することで、ソフトウェアの制御内容の妥当性を検

証し、エビデンスとします。

ETロボコンでは、C/C++の標準ライブラリの「printf関数」を使ってシステム外部に出力する使

い方が多いようです。

計測はあくまでも開発支援の機能であるため、システムの本来の性能に悪影響を与えないよう

に設計・実装する必要があります。

する必要があります。

失敗例です。 逆に、開発中に埋め込んでいた「printf関数」を本番ソフト用に取り除いてみた
