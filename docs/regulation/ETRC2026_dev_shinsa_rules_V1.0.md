クラス共通 注意事項 (1/2)

クラス共通

◼ 提出モデルは、A3用紙に印刷されて大会会場に掲示されます

印刷時に読みにくい文字サイズや画像解像度で記載されている
モデルは、減点や表彰対象外になる可能性があります
⚫ モデルはステークホルダー間のコミュニケーション促進の役割を担います

ていると判断されます

の記載を参考にしてください

◼ 提出モデルは、1ファイルにしてください

⚫ 1枚目（以下、アブストラクトページ）は、モデルテンプレートで指定した書式に

従って記述してください

2-5. 補足情報（機能実現）

ベーシック

◼ 機能実現の各項目について補足します。これは基本的な書き方であり、ここに書か

れている記法でないと評価されないというわけではありません

項目

機能

構造

振舞い

補足（基本的な例）

• 機能の明示（ユースケース）とその概要（ユースケース記述）を示してください。
• 機能の仕様は自然言語あるいはアクティビティ図などで明示します。
• 単に動作順を示すだけでなく、実現性を高めるための仕様や工夫（代替系列やリスク

への対策）まで言及されていると評価が高くなります。

• クラス図で表現される要素は、機能や仕様と結びつくよう抽出されているか、関連や属

性は妥当に定義されているか、などを評価します。

• 責務が特定のクラスに偏ることなく適切に分担されている様子が読み取れると、評価が

高くなります。

• シーケンス図などを使用して、構造で定義した要素がどのように振舞うことで機能が実

現できているかが分かるかを評価します。必要に応じて複合フラグメントを用いて処理が
読み取れると評価が高くなります。

• ステートマシン図については、ステートマシンの対象となる要素（基本的には特定のクラ
